# TG Web Media Downloader

Расширение для Microsoft Edge и Chrome (Manifest V3), чтобы скачивать фото и видео из каналов
Telegram Web — **Web K** (`web.telegram.org/k`) и **Web A** (`web.telegram.org/a`), в том числе из каналов
с запретом на сохранение контента. Только для личного использования, загружается в режиме разработчика.

**Статус:** проверено вручную — фото и видео скачиваются.

> Уважайте авторов: запрет на сохранение в канале — воля его владельца. Используйте расширение только
> для личного архива и не распространяйте скачанное без разрешения.

## Установка в Edge

1. Откройте `edge://extensions`.
2. Включите **Режим разработчика** (переключатель слева внизу).
3. Нажмите **Загрузить распакованное** и выберите папку с `manifest.json` (эту папку).
4. Обновите (F5) уже открытые вкладки Telegram Web.
5. Рекомендуется: `edge://settings/downloads`, выключить «Спрашивать, где сохранить каждый файл»,
   иначе диалог сохранения будет появляться для каждого файла.

В Chrome то же самое через `chrome://extensions`. Нужен Chromium 111 или новее (там появился `world: "MAIN"`).

Файлы сохраняются в папку загрузок браузера по шаблону `{channel}/{date}_{id}.{ext}`, например
`Downloads/Мой канал/2024-01-31_12345.mp4`. Шаблон меняется в popup. Доступные токены:
`{channel} {date} {time} {id} {type} {ext}`.

## Как пользоваться

- **Одиночное медиа.** Наведите курсор на фото или видео в ленте, появится кнопка **⬇** в правом верхнем углу.
  Её состояния: ⏳ в очереди, `NN%` загрузка, ✓ скачано, ⚠ ошибка (наведите курсор, чтобы увидеть текст ошибки).
- **Несколько медиа.** Панель **⬇ TG Downloader** внизу справа: **Режим выбора**, затем отметьте чекбоксы и
  нажмите **Скачать выбранное**.
- **Скачать всё.** На той же панели или в popup. Расширение прокручивает ленту в самый низ, а затем поднимается
  вверх, собирая медиа. Остановка: кнопкой **Стоп**, по дате («до даты включительно») или по лимиту новых файлов.
  Если открыть другой чат, процесс тоже остановится.
- **Popup** (значок расширения): очередь и прогресс, пауза и отмена, неудачные загрузки с повтором, лог,
  настройки, очистка истории дедупликации.

## Как это устроено

| Файл | Роль |
|---|---|
| `manifest.json` | MV3, права `downloads`, `storage`, хост `https://web.telegram.org/*` |
| `page/bridge.js` | MAIN world: Range-сборка через service worker Telegram, внутренний API Web K, создание blob-URL |
| `content/selectors.k.js`, `content/selectors.a.js` | **Селекторы DOM. Их правят, когда Telegram обновляет вёрстку** |
| `content/adapter.k.js`, `content/adapter.a.js` | Адаптеры клиентов с общим интерфейсом |
| `content/common.js` | Утилиты, RPC с bridge, разбор дат, общий захват через медиавьюер |
| `content/ui.js`, `content/ui.css` | Кнопки на медиа, чекбоксы, плавающая панель |
| `content/main.js` | Определение клиента, постановка в очередь, «Скачать всё», выполнение заданий |
| `background.js` | Очередь, паузы, повторы, `chrome.downloads`, дедупликация, лог |
| `popup/*` | Настройки, прогресс, ошибки |

**Web K.** Используются внутренние объекты клиента `window.appImManager.managers`. Фото скачивается
в самом большом `PhotoSize` через `apiFileManager.downloadMedia`. Видео собирается из оригинального
документа через `/k/stream/<DownloadOptions>` запросами `Range: bytes=N-`, сервис-воркер отдаёт
порции по 0,5–1 МБ. Если видео во вьюере играет через HLS, `hls/` заменяется на `stream/`: параметры
в URL одинаковые, и отдаётся исходный файл, а не перекодированное качество.
Если внутренний API пропадёт после обновления, сработает запасной путь через медиавьюер.

**Web A.** В продакшен-сборке состояние приложения со страницы недоступно, поэтому для каждого медиа
расширение кратко открывает и закрывает медиавьюер:
- фото берётся как полноразмерный blob (`photo<ID>` без суффикса размера);
- видео — по адресу `/a/progressive/document<ID>`, который затем собирается Range-запросами.

Видео, которое уже играет в ленте, берётся без открытия вьюера.

**Protected-каналы.** Клиенты прячут кнопки «Скачать» и «Переслать», блокируют контекстное меню
и копирование, а в Web A кладут поверх медиа прозрачный `.protector`. Сам поток данных через
service worker при этом не блокируется, и расширение читает его так же, как плеер клиента.

**Сохранение.** Готовый файл превращается в `blob:`-URL на странице и сохраняется через
`chrome.downloads.download`. Если браузер не даёт расширению прочитать blob страницы, расширение
автоматически переходит на клик по `<a download>` на странице, а путь и имя подставляет через
`chrome.downloads.onDeterminingFilename`. В этом режиме Edge один раз спросит разрешение
на множественные загрузки с web.telegram.org.

**Надёжность.**
- Задания выполняются последовательно, параллельно 1 или 2 (настраивается).
- Между файлами случайная пауза 1,5–3 с.
- Неудачная попытка повторяется до 3 раз с задержкой 2, 4 и 8 с. Отдельный чанк видео дополнительно повторяется внутри bridge.
- Попытка считается неудачной, если 2 минуты нет прогресса.
- Очередь хранится в `chrome.storage.session` и переживает перезапуск service worker.

**Приватность.** Расширение не делает никаких сетевых запросов, кроме относительных к самому
web.telegram.org. Данные сессии не читаются, не сохраняются и никуда не передаются.
В `chrome.storage.local` хранятся только настройки, лог и списки id скачанных сообщений.

## Чек-лист ручного теста

Каждый пункт проверить и в **Web K**, и в **Web A**:

- [ ] **Одиночное фото.** Нажать ⬇. Файл появился в `Загрузки/<канал>/<дата>_<id>.jpg`. Разрешение
      больше превью: сравнить с размером в медиавьюере, для больших фото обычно 2560 px по длинной стороне.
- [ ] **Короткое видео (до 20 МБ).** Скачивается целиком и воспроизводится. Длительность и качество как в оригинале.
- [ ] **Большое видео (больше 100 МБ).** В popup растёт прогресс в МБ, файл скачивается целиком и
      воспроизводится до конца. Размер совпадает с размером в Telegram.
- [ ] **Альбом.** Каждый элемент альбома получает свою кнопку и свой файл со своим `id`.
- [ ] **Выбор нескольких.** Режим выбора, отметить 5 медиа (фото и видео вперемешку), «Скачать выбранное»: скачаны все 5.
- [ ] **«Скачать всё» на 20+ медиа.** Лента прокручивается вверх, медиа добавляются в очередь, между
      файлами есть паузы. Отдельно проверить остановку: кнопкой «Стоп», по дате, по лимиту.
- [ ] **Повторный запуск (дедупликация).** Повторить «Скачать всё» на том же канале: всё уже скачанное
      помечено ✓ и пропущено, новых файлов нет. После «Очистить историю» в popup файлы качаются снова.
- [ ] **Дедупликация между клиентами.** Скачать в K, открыть тот же канал в A: медиа помечены ✓.
- [ ] **Обычный канал.** Все пункты выше.
- [ ] **Protected-канал** (стандартная кнопка «Скачать» скрыта): все пункты выше работают так же.
- [ ] **Ошибки.** Во время загрузки большого видео отключить сеть на 10–20 с: видны повторы в логе,
      загрузка продолжается. Закрыть вкладку во время очереди: задания попадают в «Неудачные».
- [ ] **Медиа под спойлером** (Web A): скачивается, вьюер открывается со второго клика автоматически.

## Ограничения (что технически невозможно или не сделано)

- **Web A: виден медиавьюер.** Без доступа к состоянию приложения (оно есть только в DEBUG-сборке)
  получить ID документа и полноразмерное фото можно только из DOM открытого вьюера. Поэтому при
  постановке в очередь вьюер открывается и закрывается для каждого медиа. Это заметно на экране
  и занимает 1–3 с на одно фото или видео.
- **Web A: дата берётся из локализованной подсказки** (`title` у времени сообщения). Разбор работает для
  всех языков с григорианским календарём и латинскими цифрами. Для персидского интерфейса Telegram
  (солнечный календарь) дата не распознаётся, и в имени файла будет `nodate`.
- **Web A: blob полноразмерного фото** берётся из кэша клиента в момент постановки в очередь. Если до
  обработки очереди сменить аккаунт или выйти из него, клиент освободит blob, и задание завершится ошибкой.
- **Web K: используются внутренние объекты клиента** (`window.appImManager`). После обновления Telegram они могут
  измениться. Тогда включится запасной путь через медиавьюер, и фото будет в том разрешении, которое
  вьюер выбрал под ваш экран, а не обязательно в максимальном.
- **«Скачать всё» и виртуализация ленты.** Клиенты подгружают историю порциями, расширение ждёт подгрузку
  до 6 с на шаг. На очень медленной сети прокрутка может решить, что достигнуто начало канала, раньше времени.
  В этом случае запустите ещё раз: уже скачанное будет пропущено.
- **Очень большие файлы (несколько ГБ)** собираются в Blob в памяти вкладки (Chromium выгружает крупные
  Blob на диск, но лимиты есть). Записи с экрана нет, файл всегда собирается из исходных байтов.
- **Не поддерживаются:** платные медиа, самоуничтожающиеся медиа, истории, кружочки, документы-файлы,
  стикеры и превью ссылок.
